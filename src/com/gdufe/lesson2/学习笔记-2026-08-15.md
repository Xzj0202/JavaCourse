# 学习笔记 · 2026-08-15（Git 入门全流程）

## 1. Git 是什么

**版本控制工具**：给代码拍快照、存存档点。每次 commit = 一个存档点，随时能回看、对比、回退。比「手动复制文件夹备份」强在：有历史、有差异对比、有作者记录。

## 2. 三区模型

```
工作区（你正在写的文件）
   ↓  git add   挑货：把要存的放进清单
暂存区（不是文件夹！是 .git 里的一份清单）
   ↓  git commit 拍照：真正存档
仓库（.git 里的历史存档点）
```

- 暂存区存在 `.git` 文件夹**内部**（一个叫 index 的文件），磁盘上没有叫「暂存区」的文件夹
- 看暂存区的唯一窗口：`git status` 里的 `Changes to be committed:` 段落
- 两步走的意义：commit 前给自己一个检查的机会

## 3. 今天学过的命令速查

| 命令 | 作用 |
|------|------|
| `git config --global user.name "名字"` | 配置身份（一生一次） |
| `git config --global user.email "邮箱"` | 配置身份（一生一次） |
| `git init` | 把当前文件夹变成 Git 仓库（建 .git） |
| `git status` | 查看三区状态（哪段有内容看哪段） |
| `git add .` | 当前目录所有东西挑进暂存区（黑名单除外） |
| `git commit -m "留言"` | 拍照存档，留言说明这次干了什么 |
| `git log --oneline` | 看历史存档点列表（编号 + 留言） |
| `git remote add origin 地址` | 登记云端仓库门牌号（一生一次） |
| `git branch -M main` | 把分支名 master 改成 main |
| `git push -u origin main` | 上传本地存档到云端（第一次用 -u 记路线） |
| `git push` | 之后每次只敲这两个字即可 |
| `git remote -v` | 查已登记的远端地址 |

## 4. .gitignore 黑名单

- 写进 `.gitignore` 的文件/文件夹，Git 永远无视（`git add .` 也加不进去）
- 工程规矩：**编译产物不入库**（out/ 里的 .class 随时能重新生成，没有存档价值）
- 写法：`out/`（带斜杠 = 整个文件夹）；`#` 开头是注释
- 文件名开头是英文句点（Linux 隐藏文件命名习惯），不能漏

## 5. 终端三色规律

| 颜色 | 含义 | 处理 |
|------|------|------|
| 静默无输出 | 成功 | 继续 |
| 红字 | 失败 | 读红字说了什么，对症处理 |
| 黄字（warning） | 成功但有提醒 | 看懂提醒，一般可无视 |

- 今天见过的黄字：LF will be replaced by CRLF——Windows 和 Linux 的换行符标记不同（CRLF vs LF），Git 自动转换，正常现象

## 6. 本地仓库 vs GitHub 云端仓库

- 是**两个独立的仓库**，通过门牌号（HTTPS 地址，`https://github.com/用户名/仓库名.git`）通信
- `origin` = 云端仓库的代号（约定俗成，别自己起名）
- `push` = 把本地存档上传云端；云端是异地备份 + 公开作品墙（实习简历要挂链接）

## 7. push 认证弹窗

- Git Credential Manager 弹窗 → 选「Sign in with your browser」→ 浏览器点绿色 Authorize
- 目的是验证「敲命令的人确实是账号本人」；授权过一次后，之后 push 一般不用再登录

## 8. 易错点汇总（今天踩过/预防过的）

1. `git add` 漏点号 → 报错并给 hint，读 hint 自己修
2. `git commit` 漏 `-m` → 弹 vim 编辑器卡住；逃生：`Esc` 然后 `:q!` 回车
3. 建 GitHub 仓库勾了 README → push 冲突（`failed to push some refs`）；空仓库才能无缝接上
4. remote 地址少复制 `.git` → 连不上
5. 分支名：本地 master vs GitHub 的 main → `git branch -M main` 对齐
6. 在错误的目录敲 git 命令 → 管错范围（init 必须在项目根目录）
