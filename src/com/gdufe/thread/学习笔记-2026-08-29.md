## 1. wait / notify：放锁睡觉 vs 叫醒排队

场景：线程 A 要等条件成立才能干活，不想空转烧 CPU。

- **wait()**：释放锁 + 挂起，睡进锁对象的等待队列
- **notify()**：叫醒一个睡在这把锁上的线程；醒来先排队抢锁，抢到才继续
- **notifyAll()**：叫醒全部；复杂场景拿不准就用它——反正醒来还有 while 把关

两条铁律：

1. **必须持锁调用**（在 synchronized 块/方法内），否则 `IllegalMonitorStateException`——wait/notify 操作的就是「锁对象的等待队列」，不持锁没资格操作
2. **必须用 while 不用 if**：醒来时条件不保证成立（虚假唤醒 / 被其他线程抢先改掉）——醒来 → 重查 → 不成立接着睡

### sleep vs wait（必考对比）

| | sleep | wait |
|---|---|---|
| 谁的方法 | Thread 的静态方法 | Object 的方法 |
| 对锁 | **抱着锁睡**，锁不放 | **释放锁** |
| 需要 synchronized？ | 不需要 | 必须持锁才能调 |
| 用途 | 定时 | 协作 |

### Lesson13 时间线（A 等 flag，B 置 flag 后唤醒）

```
线程A                                线程B
─────────                            ─────────
拿 lock ✓
打印「A开始等待」
while(!flag) → wait()（放锁+睡）──► 拿 lock ✓（A放出来的）
                                    sleep 1秒（抱着锁睡）
                                    flag = true
                                    notify()（叫醒A：去排队）
                                    出块，放锁
醒来 → 排队抢回 lock ✓
while 重查：flag=true → 跳出
打印「A执行了」
```

## 2. 死锁：互相等的环

- 构造：A 持 lock1 等 lock2；B 持 lock2 等 lock1 → **循环等待**，谁都不放谁也拿不到
- 代码里的 sleep(100) 是让交错必现；真实死锁是概率性的、偶发难查
- 四个必要条件：**互斥**、**占有并等待**、**不可剥夺**、**循环等待**——破坏任意一个就不会死锁；工程上最常用的破解法是**统一加锁顺序**（破坏循环等待）

### jstack 分析（Windows / Linux / Mac 通用，JDK 自带）

程序卡住时，另开终端：

```
jps -l        ← 列出所有 Java 进程，找到目标程序的 pid
jstack <pid>  ← 拉出全部线程堆栈；拉到最底，JVM 直接给出 Found one Java-level deadlock 和互相等待的环
```

注意：jstack 吃的是**进程 pid**，不是线程 id（`Thread.getId()` 是线程 id，喂给 jstack 无效）。

## 3. 生产者消费者（wait/notify 综合应用，经典面试题）

三层结构（Lesson15）：

1. **环形缓冲区**：数组 + in 写指针 + out 读指针 + count 计数；`in = (in + 1) % 10` 到尾绕回
2. **等待条件**：满了（count == 10）生产者 wait；空了（count == 0）消费者 wait
3. **唤醒**：每次生产/消费成功都 notify，叫醒可能在等的对方

关键点：

- `public synchronized void produce(...)` = `synchronized(this)`：锁 Buffer 实例本身；生产者消费者共享同一个 buffer → 同一把锁（不需要单独的 lock 字段）
- 满时推演：P 进 while → wait 放锁 → C 抢锁消费 count=9 → notify → P 醒来重抢锁 → 重查 9≠10 → 继续生产
- 程序能正常结束的原因：生产总量 40 = 消费总量 40；若两边数量不等，多等的一方会在 wait 里永远等下去（真实系统要有退出机制，如「毒丸」，以后讲）

## 4. 易错点

1. wait/notify 不在 synchronized 里调用 → `IllegalMonitorStateException`
2. wait 用 if 不用 while → 虚假唤醒后条件不成立还往下走
3. notify 后锁不会立刻放——要等 synchronized 块结束才放，被叫醒的线程也得等锁空出来
4. 两边的 wait/notify 必须是**同一个锁对象**——不同对象互相喊话听不见
5. 死锁程序不报错、只是卡住——要靠 jstack 这类外部工具「拍照」定位
