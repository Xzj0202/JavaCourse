# 学习笔记 · 2026-08-29（多线程第二天：线程协作）

## 1. wait/notify机制

### 基本概念
- **wait()**：让当前线程等待，释放锁，进入等待状态
- **notify()**：随机唤醒一个等待该锁的线程
- **notifyAll()**：唤醒所有等待该锁的线程

### 使用规则
1. **必须在synchronized块内调用**
   ```java
   synchronized (lock) {
       wait();  // 或 notify()
   }
   ```

2. **必须用while循环，不能用if**
   ```java
   // 正确做法
   while (!condition) {
       wait();
   }
   
   // 错误做法（可能虚假唤醒）
   if (!condition) {
       wait();
   }
   ```

3. **虚假唤醒**：JVM可能随机唤醒线程，即使条件未满足，所以必须重新检查

### 示例代码
```java
// 线程等待
synchronized (lock) {
    while (!flag) {
        lock.wait();  // 等待flag变为true
    }
    // 执行后续代码
}

// 线程唤醒
synchronized (lock) {
    flag = true;  // 设置条件
    lock.notify(); // 唤醒等待的线程
}
```

## 2. 死锁构造与分析

### 死锁条件（四个必要条件）
1. **互斥条件**：资源每次只能被一个进程使用
2. **占有并等待**：进程保持资源并等待其他资源
3. **不可剥夺**：资源不能被强制释放
4. **循环等待**：进程间形成等待链

### 死锁构造示例
```java
// 两个锁
Object lock1 = new Object();
Object lock2 = new Object();

// 线程A：先lock1，再lock2
new Thread(() -> {
    synchronized (lock1) {
        System.out.println("线程A获取lock1");
        Thread.sleep(100);
        synchronized (lock2) {
            System.out.println("线程A获取lock2");
        }
    }
}).start();

// 线程B：先lock2，再lock1
new Thread(() -> {
    synchronized (lock2) {
        System.out.println("线程B获取lock2");
        Thread.sleep(100);
        synchronized (lock1) {
            System.out.println("线程B获取lock1");
        }
    }
}).start();
```

### jstack分析（Linux/Mac）
```bash
jstack <进程ID> > deadlock.txt
```
分析结果会显示"Found one Java-level deadlock"和线程等待关系。

## 3. 生产者消费者模型

### 核心要素
1. **生产者**：生产数据放入缓冲区
2. **消费者**：从缓冲区取出数据
3. **缓冲区**：有限容量的队列
4. **同步机制**：解决缓冲区满/空的问题

### 实现要点
```java
class Buffer {
    private Object lock = new Object();
    private Object[] buffer = new Object[10];
    private int count = 0;
    private int in = 0, out = 0;
    
    // 生产
    public synchronized void produce(Object data) throws InterruptedException {
        while (count == buffer.length) {
            wait(); // 缓冲区满，等待
        }
        buffer[in] = data;
        in = (in + 1) % buffer.length;
        count++;
        notify(); // 唤醒消费者
    }
    
    // 消费
    public synchronized Object consume() throws InterruptedException {
        while (count == 0) {
            wait(); // 缓冲区空，等待
        }
        Object data = buffer[out];
        out = (out + 1) % buffer.length;
        count--;
        notify(); // 唤醒生产者
        return data;
    }
}
```

### 关键点说明
1. **环形缓冲区**：使用取模运算实现循环使用数组空间
2. **条件判断用while**：防止虚假唤醒
3. **生产后notify消费者**：唤醒可能等待的消费者
4. **消费后notify生产者**：唤醒可能等待的生产者
5. **synchronized方法**：保证操作的原子性

## 4. 易错点总结

1. **wait/notify必须在synchronized中**
   - 否则抛出IllegalMonitorStateException

2. **wait要用while循环**
   - JVM可能虚假唤醒，需要重新检查条件

3. **notify不会立即释放锁**
   - 要等到synchronized块结束才释放

4. **锁的对象要一致**
   - wait和notify必须在同一个锁对象上调用

5. **死锁检测困难**
   - 程序会卡住不动，需要外部工具分析

## 5. 常见异常处理

### InterruptedException
```java
try {
    wait();
} catch (InterruptedException e) {
    // 处理中断异常
    Thread.currentThread().interrupt(); // 恢复中断状态
    return;
}
```

### NoClassDefFoundError
- 运行时找不到类的字节码文件
- 检查.class文件是否完整（内部类会生成$命名的文件）

## 6. 性能考虑

1. **锁的粒度要小**
   - 只锁必要的代码段，不要锁整个循环

2. **避免不必要的等待**
   - 在while循环中快速判断条件

3. **考虑使用Lock接口**
   - 相比synchronized更灵活，支持公平锁等特性
