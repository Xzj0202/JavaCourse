# 学习笔记 · 2026-08-30（volatile / 死锁预防 / jstack 实操）

## 1. 可见性 vs 原子性：竞态条件的完整故事

- 8-28 学的竞态条件是**一半真相**：`count++` 三步被切断 = **原子性缺失** → synchronized 解决（管排队）
- 今天补**另一半**：一个线程改了共享变量，另一个可能永远看不到 = **可见性缺失** → volatile 解决（管传话）
- 一句话分工：**synchronized 管排队（一次一个进），volatile 管传话（改了立刻全员知道）**

## 2. volatile

### 原理（三句话）
1. JIT 编译器看到 `while(running)` 的循环体里没人改 running，就优化成「读一次反复用」→ worker 只盯自己手里的旧副本
2. main 改了 running，worker 根本不去主内存看新值 → 循环停不下来
3. 程序不报错、不死锁、**就是停不下来**——比崩溃阴险

### VisibilityDemo 两轮现象
| 版本 | 现象 |
|---|---|
| 不加 volatile | main 打印「已置 false」后永远沉默，worker 聋转（1 秒数 46 亿圈 = JIT 优化后满速空转） |
| 加 volatile | worker 立刻听见叫停，打印计数正常退出 |

### volatile 保证 / 不保证
| 事项 | 保证？ |
|---|---|
| 写立刻刷主内存、读强制看主内存（可见性） | ✅ |
| 复合操作原子性（count++ 三步） | ❌ 照样丢更新 |
| 替代锁（排队互斥） | ❌ 排队还得 synchronized |

- **面试陷阱：volatile 不保原子性**。`volatile int count; count++` 仍需锁
- 共享标志位铁律：**要么 volatile，要么全程锁保护，二选一，裸奔必出事**

### 悬案回收：WaitNotifyDemo 的 flag 为什么没出事
flag 没加 volatile 但所有读写都在 synchronized 块里——JVM 进出锁时会同步主内存，锁自带传话效果。

## 3. 死锁预防：破坏循环等待

- 死锁版：A 要「lock1→lock2」，B 要「lock2→lock1」，等待线互指成环 → 永卡
- 预防版：A、B 都「lock1→lock2」（**全局统一加锁顺序**）→ 等到的是迟早会放手的人 → 环画不出来
- 通用法则：所有线程按同一全局顺序拿锁；死锁四条件之一（循环等待）被破坏，死锁从根上不可能发生
- DeadlockDemo 留存预防版；想复现死锁做 jstack 实操，按 main 里注释把 TaskB 两个块对调即可

## 4. jstack 实操手册（Windows 完全可用）

```
jps -l                      ← 列出 Java 进程，认准目标程序那行的 pid（排除 jps 自己、VSCode 语言服务器）
jstack <pid>                ← 拉全部线程堆栈，滚到最底看 Found one Java-level deadlock
```

- `locked <0x...>` = 已持锁；`waiting to lock <0x...>` = 在等；两个 object 地址就是你的 lock1/lock2——JVM 直接画环，不用人肉分析
- `monitor 0x...` 是 JVM 内部锁结构地址，看 object 行就够
- 报「无法将 jps 识别为 cmdlet…」= PATH 里找不到 → 绝对路径调用（路径带空格必须引号 + `&`）：
  `& "D:\Program Files\Java\jdk-26.0.2\bin\jps.exe" -l`
- 程序卡住的正规停法：**Ctrl + C**（叉终端是最后手段）
- 工程习惯：`new Thread(task, "线程A")` 起名——默认名 Thread-0/1 在 jstack 报告里认不出谁是谁

## 5. WaitNotifyDemo 时序判读

| 时序 | 谁先抢到锁 | 输出顺序 |
|---|---|---|
| 标准 | A → wait 放锁 → B 进 | A等待 → B设置flag → A执行 |
| 变体 | B 抱锁睡 1 秒，A 门口等 | B设置flag → A等待（跳过wait）→ A执行 |

两种都合法——**多线程输出顺序不由代码顺序决定，由抢锁顺序决定**。判读法：看 B 的行在中间还是最前。

## 6. 报错对照表新增

| 报错/现象 | 含义与处置 |
|---|---|
| 无法将 xxx 识别为 cmdlet… | PATH 找不到命令 → 绝对路径 + & 调用 |
| 程序卡住不退出 | 先想死锁/永久等待 → jstack 拍照 → Ctrl+C 收场 |
| main 置 false 后 worker 停不下来 | 可见性缺失 → 加 volatile 或锁保护 |
