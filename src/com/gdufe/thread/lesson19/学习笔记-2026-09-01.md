# 学习笔记-2026-09-01（lesson19 线程池 ExecutorService）

## 概念

### 为什么用线程池

- 线程创建有成本：内核线程 + 默认约 1MB 栈内存；无节制 `new Thread` → 上下文切换爆表甚至 OOM
- 线程池 = 固定数量 worker 线程 + 任务队列：复用线程，任务多时排队而非新建

### 线程池三件套

```java
ExecutorService pool = Executors.newFixedThreadPool(3); // 1) 建池：3 个 worker
pool.submit(任务);                                       // 2) 交活：Runnable（无返回）/ Callable（有返回）
pool.shutdown();                                        // 3) 关池：不再接新活，干完手头的才退
```

- **不写 shutdown → 程序不退**：worker 是非守护线程，main 结束它们不死，JVM 永不退出（现象：任务打印完卡住，Ctrl+C 停）
- `shutdown()` = 温柔关门（干完手头活）；`shutdownNow()` = 暴力打断（知道有即可）
- shutdown 后再 submit → `RejectedExecutionException`（默认拒绝策略 **AbortPolicy** = 直接抛异常；另有 CallerRunsPolicy「谁交谁自己干」、DiscardPolicy「悄悄丢」）
- 异常消息里的 `[Shutting down, pool size = 3, active threads = 3, queued tasks = 7, completed tasks = 0]` 是池子当时快照：关门中、3 个工人都忙、7 个排队、0 完成
- `submit(Runnable)` 内部把任务包装成 `FutureTask` 再交给池子（异常消息里能看到）
- **main 抛异常不影响 worker**：10 个任务照干完，池空 JVM 才退——异常只炸当前线程

### Callable vs Runnable

| | Runnable | Callable\<T\> |
|---|---|---|
| 方法 | `void run()` | `T call()` |
| 返回值 | 无 | 有（泛型 T） |
| 抛异常 | 签名不能 throws | 声明 `throws Exception` |

- `Future<T>` = 取货单：`submit` 立刻返回，此时活可能还没干完；`get()` 阻塞等结果
- **为什么 main 能 throws 而 run() 不能**：main 的签名允许声明 throws；`Runnable.run` 接口签名里没声明抛异常。「能不能 throws」看签名授权

### 可见性 vs 原子性（开场抽查，昨日复习）

- `count++` = 读-改-写三步；volatile 保证每次读最新、每次写立刻广播，但**管不住三步之间被插队** → 两个线程读到同一个旧值 10，都写回 11 → 两次 +1 只涨 1
- `AtomicInteger.incrementAndGet()` = CAS 一条硬件指令，三步合一没有中间状态 → 不丢
- 比喻：synchronized 是排队（独占）、volatile 是传话（保证送达不打包）、原子类是动作（一步做完不让插队）

## 报错对照

| 报错 | 原因 | 解法 |
|---|---|---|
| 找不到或无法加载主类 `...*` | java 用了通配符 | javac 认 `*.java`，java 只认具体主类全名 |
| RejectedExecutionException | shutdown 后还 submit | 预期行为；把 submit 挪到 shutdown 前 |
| 找不到符号 Println | 大小写错 | `System.out.println`，方法名全小写 |
| 找不到符号 sleep | sleep 是 Thread 的静态方法 | `Thread.sleep(50)`，且 run() 里只能 try/catch |
| 非法字符 | 全角分号 `；` | 半角 `;` |

## 易错点

- 忘 `shutdown()` → 程序不退
- `Future.get()` 阻塞主线程，不是轮询
- 高斯公式 `(1+n)*n/2` 在 n 约 5 万时 `(1+n)*n` 溢出 int（静默绕回）→ 中间量换 `long`
- 已完成的 TODO 注释要删除：TODO 代表「待办」，留着会误导读者（工程习惯）
- 任务输出顺序乱（8 在 7 前）不是 bug：并发下谁抢到线程谁先跑
