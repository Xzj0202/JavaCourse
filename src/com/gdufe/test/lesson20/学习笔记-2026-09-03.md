# 学习笔记-2026-09-03（lesson20 JUnit 单元测试入门）

> 补 09-02 的课。素材：给 MyArrayList 的 main 人眼验证升级为 JUnit 断言自动判卷。

## 概念

### jar 是什么

- 自己的代码 = 散装 .class 文件（out 目录里），`java -cp out` 告诉 JVM 去目录里找类
- 别人的代码（几千个 .class）发布时打成一个压缩包 = **jar**（本质 zip，后缀 .jar，装的全是 .class）
- **JUnit** = Java 世界写单元测试的标准工具（类比 git 之于版本控制）；下载的 jar 就是把这套判卷工具搬回家

### 三个新词

| 词 | 一句话 |
|---|---|
| 注解 @Test | 贴在方法上的**标签**，本身不是语句；JUnit 扫描器挑出贴了标签的方法逐个跑，没贴的不理 |
| import static | 静态导入：导入类里的**静态方法**，裸调 `assertEquals(...)` 不带类名前缀。普通 import 省包名，静态导入连类名也省 |
| lambda | 一段打包成「值」的代码：`() -> small.get(-1)`。对照 C++ `[&](){...}`——捕获列表不用写，`->` 替代 |

静态方法早用过：`Thread.sleep(50)`、`Math.abs(x)`——不 new 对象、类名直接调。

### 断言两件套

```java
assertEquals(期望, 实际);      // 相等→绿，不等→红：expected: <15> but was: <10>
assertThrows(异常类.class, () -> 代码);   // 断言这段代码必抛该异常；没抛或抛错类型→红
```

- 期望永远写前面；写反测试照样跑，但报错信息误导人
- `.class` = 把「类本身」当值传（不是 new 对象）
- assertThrows 必须用 lambda：代码要**打包递给** JUnit 执行，不能当场执行（当场就炸了，走不到判卷）

### 测试是三幕剧

```
第 1 幕 搭台：造数据（add 一堆）
第 2 幕 演出：执行被测动作（add 第 11 个 / remove(1)）
第 3 幕 判卷：断言（capacity、size、get 的值）
```

断言只是「验」，**验之前必须有动作发生过**。测试方法名 = 行为一句话（`addTriggersGrow` = add 触发扩容），命名即文档。

### 为什么 JUnit 强过 main 打印

- main 里测试 4 抛异常 → 程序当场死，测试 5 永远跑不到
- JUnit 每个 @Test 方法**独立战场**：一个红不影响其他照跑，最后汇总红绿榜

## 命令表

```powershell
# 编译：两个源文件一起递，jar 进 classpath（javac 要找 JUnit 类的定义）
javac -cp "lib/junit-platform-console-standalone-1.13.4.jar" -d out src/.../MyArrayList.java src/.../MyArrayListTest.java

# 运行：跑的是 JUnit 官方 main（-jar 模式），它去 out 找你的测试类
java -jar lib/junit-platform-console-standalone-1.13.4.jar -cp out --select-class com.gdufe.test.lesson20.MyArrayListTest
```

- 两行 `-cp` 装的东西不同：javac 装 **jar**（编译期找定义）；JUnit 启动器装 **out**（运行期找你的类）。`-cp` 回答的永远是「去哪找类」
- 新版写法（本次出现的 deprecate 提醒）：`java -jar xxx.jar execute --select-class ...`，加 `execute` 子命令
- jar 不进 git：`.gitignore` 加 `lib/`——二进制依赖进仓库只胖不瘦（git 历史只增不减）；11 月 Maven 会把下载/classpath/git 排除全自动

## 测试报告读法

- 树形结构：Platform → Jupiter 引擎 → 你的测试类 → 各方法 [OK]
- 日常扫两个数：`tests found`（该跑几条）、`tests failed`（挂了几条）
- 红了：方法行变 [X]，下方给出断言位置（如 `MyArrayListTest.java:43`）——**从上往下找第一个指向自己文件的位置**，别在 WARNING 里打转

## 报错/警告对照

| 现象 | 原因 | 处理 |
|---|---|---|
| ren 报「源路径和目标路径必须不同」 | Windows 文件系统不区分大小写（Lesson20==lesson20） | 两步改名：先 ren 成中转名再 ren 回目标名 |
| 找不到符号 list | 声明的变量叫 big/small，用的却是 list（笔误） | javac 前自查变量名一致性 |
| javac 注：未经检查或不安全的操作 | MyArrayList 里 `(E) elementData[index]` 强转（泛型擦除，待讲） | 非错误，学泛型时彻底讲 |
| WARNING final field mutation | JUnit jar 内部实现被新 JDK 提醒 | 与你的代码无关，无视 |
| WARNING Delegated to 'execute' | 调用方式为旧式写法 | 记下新写法即可 |

**控制台一大坨输出时，先分「谁的锅」**：结果树和 tests failed 是你的成绩；WARNING 先问「谁写的代码引起的」再决定理不理。

## 易错点

- assertEquals 参数顺序：期望在前、实际在后
- 测试方法规矩：非 static、返回 void、无参数、贴 @Test；方法名读成一句话
- 手写 20 行断言必出 `get(20)` 式越界手滑——用 for 循环断言，手滑自动消失
- 每条测试自己搭台：方法 A 的数据方法 B 用不到
