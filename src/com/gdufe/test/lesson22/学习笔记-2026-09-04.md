# 学习笔记-2026-09-04（lesson22 独立测试设计课）

## 核心方法：场景从哪来

凭空想场景 → 想不出。场景藏在两个地方：

**① 契约**——每个 public 方法是一份承诺：
- 兑现什么：正常输入下返回什么、改了什么状态（返回值 / size / capacity / 内容）
- 拒收什么：哪些输入该抛异常（越界、空表）

**② 风险**——实现里最容易错的边角：空、满、删尾、扩容跳变

## 覆盖倒查表（今天的核心工具）

| 方向 | 读法 | 用途 |
|---|---|---|
| 每条测试的注释（顺读） | 这条测试 → 测什么 | 讲清单条意图 |
| 覆盖表（倒查） | 方法 → 被谁测过 | **看见没人测的方法**——漏测只有倒查能暴露 |

表：行是 API（含两个构造器），列是兑现/拒收。**空格 = 候选场景。**

## 命名公式

方法名 = **动作 + 结果**，读出来是一句话：

| 旧 | 新 | 读作 |
|---|---|---|
| newTest | `newListStartsEmptyAtCapacity10` | 新列表以容量 10 空着起步 |
| getNullTest | `getOnEmptyListThrows` | 空表上取数就抛 |
| addAndGetTest | `addAndGetInOrder` | 存进去按序取回 |
| removeTest | `removeTwiceStillShifts` | 删两次照样搬移 |
| growTest | `addTriggersGrowFrom10To15` | add 触发扩容，10 到 15 |

- "Test" 后缀冗余（@Test 已贴标签）；**名字即文档**，注释可删可留

## 易错点（今天踩过的）

| 现象 | 原因 | 处理 |
|---|---|---|
| `expected: <9> but was: <10>`（growTest 红） | capacity 是**数组长度**不是元素数，9 个装得下不扩容 | 扩容只在「满了还加」触发：10→15 在第 11 个 add |
| assertThrows 编译错 | 只递了代码，没递判卷标准 | `assertThrows(异常类.class, () -> 代码)` 两参数缺一不可 |
| 裸类型 `MyArrayList list` | get 返回 Object，编译器不查类型 | 写全 `MyArrayList<Integer>`（根因等泛型擦除课） |
| 一个方法塞两个场景 | 红了说不清哪坏 | 一个行为一个方法，方法名=一句话 |
| 没跑就交（×2） | 把判卷权还给导师 | **改完 → 编译 → 跑 → 全绿 → 才说"好了"** |

## 开场抽查回顾（扩容边界迁移题）

- `put13thTriggersGrow` 循环 12 改 13：**会挂**——第 13 个新 key put 完 size=13 > 16×0.75=12，扩容已发生，`assertEquals(16,...)` 必红
- **覆盖分支不计数**：重复 put 走「改 value + return」，不 ++size、不查扩容
- 边界表述：**第 13 个「新 key」触发扩容，不是第 13 次 put**
- JUnit **fail-fast**：首条断言失败即终止本测试方法，后面断言执行不到
