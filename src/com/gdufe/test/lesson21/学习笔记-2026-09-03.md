# 学习笔记-2026-09-03（lesson21 测试思维——该测什么，自己说了算）

> 素材：给 MyHashMap 写测试（比 MyArrayList 险恶：链表、覆盖、扩容搬家）。

## 概念

### 三句话提问法（对每个方法依次问）

```
1. 它正常干活时承诺什么？      → put 进去的东西，get 必须原样吐出来
2. 重复干会怎样？              → 同 key put 两次：覆盖还是共存？
3. 捣乱呢？（不存在的、null、超量）→ get 没存过的 key 返回什么？
```

自己的 main 就是最现成的题库：main 里**肉眼验证过的每件事 = 一条测试场景**。

### 一条测试盯一种死法（本课核心）

MyHashMapTest 8 条测试各有岗位，看似重复实则各守一个故障：

| 测试 | 盯的「死法」 |
|---|---|
| putAndGetBasic | put/get 基本存取坏 |
| putSameKeyUpdatesValue | 覆盖写坏：链表里出现重复节点（size 变 2）、或值没换 |
| getMissingKeyReturnsNull | 不存在的 key 抛异常或返回垃圾值 |
| removeReturnsValueAndCleansUp | 删完没断链（get 还能取到）、返回值错、size 没减 |
| removeMissingKeyReturnsNull | 删不存在的 key 抛异常 |
| put13thTriggersGrow | 扩容时机错（早扩/晚扩/不扩） |
| oldDataSurvivesResize | **rehash 写坏：搬家丢节点、链接错**（前面 6 条全绿它独红） |
| nullKeyCanBeStoredAndFetched | indexFor 特判被删 → NPE |

关键推演：**前面 6 条每条最多放 3 个元素，`3 > 12` 不成立 → resize 从头到尾没跑过**；第 7 条放 20 个才让 resize 真正执行。测「搬家前」和测「搬家后」是两回事。

### assertNull

`assertNull(x)` ≡ `assertEquals(null, x)` 的专用速写，读代码一眼知道在验 null。

### 扩容边界（算过才断言）

```
默认容量 16 × 负载因子 0.75 = 12
触发条件 size > 12（大于，不是大于等于）
→ 12 个时不扩（12 > 12 不成立），第 13 个 put 落地后扩 16→32
```

### null key 为什么不炸

```java
private int indexFor(Object key) {
    if (key == null) {
        return 0;    // 特判：null 固定落 0 号桶
    }
    return key.hashCode() & (table.length - 1);   // 没特判：null.hashCode() → NPE
}
```

null 上调方法 = NullPointerException（8 月学的 NPE 的来源之一）。这条测试盯的是「看起来就该炸的输入，特判让它活下来了」。

### 副作用断言

一条测试可以多个断言：验行为 + 验副作用。覆盖那条同时断言「值换了」和「size 没变」——size 就是 put 覆盖路径的副作用。

## 易错点

- 「测试空值」≠「get 不存在的 key」：key 不存在 ≠ 值是空，措辞要准
- remove 没有置空逻辑：三件事是返回被删值、再取取不到、size 减 1
- 扩容断言先算 16×0.75 再写数字，拍脑袋必红
- JUnit 每个 @Test 独立战场：方法 A put 的数据方法 B 用不到
- 设计场景卡壳时的兜底流程：先列白话清单发导师审 → 审完再动手写码
