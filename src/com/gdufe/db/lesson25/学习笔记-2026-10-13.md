# 学习笔记 2026-10-13 · lesson25（DDL 建表）

## 一、DDL 与 DML

| 分类 | 全称 | 干什么 | 例子 |
|---|---|---|---|
| **DDL** | Data Definition Language | 定义**结构** | `CREATE TABLE` / `ALTER TABLE` / `DROP TABLE` |
| **DML** | Data Manipulation Language | 操作**数据** | `INSERT` / `SELECT` / `UPDATE` / `DELETE` |

## 二、CREATE TABLE 的两段式结构 ★

```sql
CREATE TABLE 表名 (

    列名  类型  列属性,          ← 第一段：列定义清单（"有哪些格子、装什么"）
    列名  类型  列属性,

    FOREIGN KEY (列名) REFERENCES 另一张表(列名)   ← 第二段：表级约束（写在列清单【之后】）
);
```

**顺序是死的**：先把所有列列完，再写约束。在列的位置直接写 `FOREIGN KEY(...)` 会报语法错——因为那一列没有类型。

## 三、数据类型

| 类型 | 含义 | 备注 |
|---|---|---|
| `INT` | 整数 | |
| `VARCHAR(n)` | 最多 n 个**字符**的文本 | 中文也算 1 个字符；不是字节 |
| `DATETIME` | 日期+时间 | |

## 四、列属性

| 写法 | 含义 |
|---|---|
| `PRIMARY KEY` | 主键：这一行的唯一身份证 |
| `AUTO_INCREMENT` | 插入时不填，自动 +1 |
| `NOT NULL` | 不允许为空 |
| `UNIQUE` | 值不允许重复 |
| `DEFAULT 1` | 不填时用默认值 1 |
| （什么都不写） | 允许为空 `NULL` |

> ⚠️ **`KEY` 的一词两义**：写在**列定义**里等价于 `PRIMARY KEY`（能跑）；写到**表级位置**就变成"普通索引"了。**一律写全 `PRIMARY KEY`**，少踩坑。

## 五、外键 FOREIGN KEY

```sql
FOREIGN KEY (本表列) REFERENCES 目标表(目标列)
```

**为什么用**：保证 `borrow_record.book_id` 里填的必然是 `book` 表里真实存在的 id —— 借书不可能借到一本不存在的书。这是关系型数据库的核心机制，面试必问。

**硬要求**：

1. **两边类型必须完全一致**（都 `INT`），差一点就报错
2. **必须先建父表**（先 `book`/`reader`，再 `borrow_record`），否则报 `Cannot add foreign key constraint`
3. 引擎需为 InnoDB（MySQL 8 默认就是，不用管）

## 七、语法规则与易错点

- **注释必须是 `-- `（两道杠 + 至少一个空格）**。写 `--注释` MySQL 不认，会当成减号运算去解析，直接语法错。
- 表名/字段名**一律小写英文**，不用中文、不用空格、不用 SQL 关键字（`order`/`key`/`desc` 都是雷）
- 表名用**单数**：`book` 而不是 `books`，全库保持一致
- 每条语句结尾 `;` 别漏
- 字符集不用写：MySQL 8 默认 `utf8mb4`，中文没问题

## 八、报错对照表

| 报错 | 原因 |
|---|---|
| `ERROR 1064 (42000) ... syntax error` | 语法错：括号写错 / 漏分号 / 注释格式不对 |
| `ERROR 1050 ... Table already exists` | 重复建同名表 |
| `ERROR 1215 / 1824 Cannot add foreign key constraint` | 外键建不上：类型不一致 / 父表不存在（顺序错了）/ 表名拼错 |

## 九、怎么验证表建对了

```sql
SHOW CREATE TABLE borrow_record;     -- 看完整建表语句（含外键）

SELECT COUNT(*) AS fk_count          -- 只回一个数字，适合不看 GUI 时核对
FROM information_schema.TABLE_CONSTRAINTS
WHERE CONSTRAINT_SCHEMA = 'library'
  AND TABLE_NAME = 'borrow_record'
  AND CONSTRAINT_TYPE = 'FOREIGN KEY';
```

**`information_schema`** = MySQL 的"元数据库"，数据库用它描述自己：所有库、表、列、约束、索引都记在里面。插件默认把它藏起来，它却一直在那儿。
